## 구현

#790의 네 실행 경로를 하나의 Core 변경 단위로 검증한다. 같은 main을
기반으로 한 #796 교육 / #797 돌봄의 변경만 선택적으로 재사용하며,
교역·가구 이주를 추가한다. 기존 PR을 병합하거나 변경하지 않는다.

- **교육**: 실제 교사 지식·기록된 사실·학습자 지식 차이·거리·생존·
  현재 작업 검증 후 학습자 순위만 조정한다. 실제 교육 점수와 완료 토큰은 유지한다.
- **돌봄**: 실제 기존 Parenting 후보 및 응급 식량 조달 후보의 순위만
  조정한다. 가족·아동 단계·재고·거리·돌봄자 생존 판정을 우회하지 않는다.
- **교역**: 실제 가까운 상호 교환 후보 및 정착지 간 교역 상대·여행자
  후보를 선호할 수 있다. 실제 교환 점수, 물자/보호 재고, 동의,
  경로 검사, 생존 중단, 영속적 여행 재개와 귀환 의무는 그대로다.
- **가구 이주**: 실제 희소성·여행 부담·구성원 자율성·공동 압력을
  충족한 가구와 지도자 후보만 선호한다. 목적지는 기존 Core frontier
  선택을 사용한다. 영유아 운반 미구현을 도보 이동으로 위조하지 않는다.

공통 선호는 주민당 **가장 최근의 단일 수락 입력**만 사용하고,
1일·유한 우선순위 ≥0.55·실제 생존 대상·유효 저널을 요구한다.
후보당 보너스는 최대 0.12이며 여러 사람의 선호를 누적하지 않는다.
더 최신의 다른 생각이 있으면 과거 생각은 적용되지 않는다.
수락 자체가 실행·성공·새 자원·관계 변화·학습 사실을 만들지 않는다.

스냅샷 포맷이나 브라우저 권위는 추가하지 않는다. 기존 accepted journal,
pending context, trade journey codec과 결정론 실행을 재사용한다.
모델이 없어도 기존 Core 선택은 계속 작동한다.

- 교육·돌봄: 실제 선택 대상 비교, 기존 pending token, 저장 복원.
  #797에서 가져온 돌봄 테스트는 CHECK 실패가 bool 성공으로 해석되던
  오류도 수정하여 정수 종료 코드로 실패를 전달한다.
- 교역: 실제 세 주민 재고 이동의 상대 변경, 무재고·원거리 차단,
  과거/미래/비유한/낮은 우선순위·사망·새 목표 guard,
  바이너리 byte-stable 저장·복원과 동일 결과.
- 정착지 교역: 두 유효 상대 간 선택 비교와 실제 수락 입력을 포함한
  기존 출발→물리 이동→교환→귀환·생존 중단/재개 회귀.
- 가구 이주: 동일 압력의 두 가구 중 선택, 합의/압력 유지, 영유아 및
  압력 없는 이주 거부, 실제 runtime 이동·토큰·binary replay.
