# LifeLens 시각지도 전환 — P0 (실제 Core 기반 시각화 실험)

상태: **PR 실험 / 기본 렌더러 교체 아님**
기준: main 4a4e2a3a (2026-11-16)
방향: 참고 게임의 환경 식별성과 지역맵 계층을 관찰형 시뮬레이션에 맞게 응용한다. 특정 게임의 이미지·에셋·코드를 복제하지 않는다.

## 목적

라이프렌즈의 단일 시뮬레이션 Core를 유지하며, (1) 숲·암석·수계가 한눈에 읽히는 색채형 지역 지도, (2) 정착지·주민 위치의 사실 기반 투영, (3) 현장 관찰과 지역 지도 왕복을 먼저 확인한다. 2.5D 실제 월드 화면 교체 여부는 P0 검증 이후에 결정한다.

## 설계 원칙

- **권위 경계**: LifeLensCore(C++)와 저장/학습/행동/지형 생성 변경 없음. 지형은 ObserverSnapshot.terrain; 정착지는 civilization.settlements; 주민은 실제 hasPosition/gridX/gridY만 소비한다.
- **렌더러 독립**: 지역 지도는 독립 Canvas 2D. 기존 WorldScene 3D, 비상 Canvas 2D, EarthGlobePreview 유지. WebGL context를 새로 만들지 않는다.
- **관측 범위 정직성**: 현재 Core가 전달한 8~16 청크 반경 window만 그린다. 빈 영역을 미탐험·발견 불가 지역이라고 표기하지 않는다. 클릭은 실제 전달된 chunk에만 반응한다.
- **시각 vs 실체 구분**: 화면의 전나무·꽃·돌은 Core의 forest/grass/rock coverage를 나타내는 *시각 기호*일 뿐 개별 벌목 대상·채집 노드·광맥이라고 주장하지 않는다. 실제 주민·정착지 마커만 권위 DTO에서 생성한다.
- **모바일 안전**: GPU 없는 Canvas로 동작하고 지도 오픈 시 기존 3D 루프를 가린다. 표시 자체는 simulation speed, save, restore, Core chronology를 바꾸지 않는다.
- **기능 미포함**: 세계 전체 캐시/멀리 있는 지역 스트리밍, 이동 경로 예측, '탐험/안개', 지도로 주민 통제, 신설 유료 서비스, 새로운 게임 규칙.

## P0 실제 구현

1. '지역 지도'로 오버레이 열기. '지구 관찰'과 상호 배타적.
2. Core 전달 청크별 물/숲/암석/초원 표현; 월드 시드+청크를 키로 한 결정적 장식.
3. Core resident 위치와 active settlement 표시. 주변 지점 탭 시 observer 중심 이동.
4. 지도 드래그, 확대/축소, 현재 위치, 닫기.
5. 기존 3D와 호환 Canvas, 시뮬레이션 저장/AI/Core 무변경.
6. Shared web presentation regression에 렌더링 결정성·Core 비가용 차단·관측 청크 hit test 추가.

| 단계 | 목적 | 인수 조건 |
| --- | --- | --- |
| P1 | 실제 3D 월드 식생·바위·지면의 일관된 스타일 재구성 | 동일 Seed의 기존 WorldScene과 시각 비교, 나무/암석/잔디 인과 불변 |

| P3 | 주민·시설·자원 현장 통합 | 기존 GLB 모션/행동/작업위치·시설 사용·자원 반영 유지 |

| P5 | 모바일 메모리/프레임/장시간 호환 비교 | GPU/Canvas 각각 오류·누수·입력 지연 측정 후 기본 전환 판단 |

## 시험·보류

자동 확인 대상: npm run typecheck, node tests/presentation/run.mjs, npm run build (web 디렉터리), 기존 Tools/ci_web.py regressions와 기본 Web Checks CI.

수동/실환경 확인 대상: 기존 세계 로드 → 지역 지도 열기 → 줌/드래그/탭 → 실제 현장으로 되돌아가 동일 주민·위치 확인 → 저장 후 재접속, 모바일 360/390px 가로·세로, 지역 내 신생 정착지 갱신 확인, 3D 렌더러와 Canvas 호환 모드 각각 작동 확인.

**P0 완료 판단은 CI와 위 기능 검수에 의존한다.** P0 성공만으로 실제 2.5D 월드 시각품질/모바일 성능 개선 또는 행성 전체 광역맵 구현 완료로 간주하지 않는다.
