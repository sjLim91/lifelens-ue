# 실제 식물 자원과 야생동물·주민 생존 연결

기준 main: `3162b2debd9e4d54148a9710662808b496c3d994`.
사용자 요청에 따라 클론 없이 GitHub 연결 도구로 읽기·브랜치·커밋·PR을 진행했다.

## 확인한 원인

- 기존 production wildlife는 고정된 `habitat.forage01` 확률로 초식동물 허기를 줄이고 실제 ResourceNode를 소비하지 않았다.
- 번식은 개체 수 상한·나이·부모 허기만 확인하므로 실제 식량 부족과 분리돼 있었다.
- 주민에게 살아 있는 동물을 대상으로 이동·사냥·식사를 완료하는 경로가 없었다.
- 늑대·호랑이 포식은 존재하지만, 주민과 가까우면 회피하고 개별 위치/거리 조건을 만족해야 한다. 포식자 추가만으로 결손 식량 연결을 해결할 수 없다.

## 변경

- Simulation이 시간 경계마다 실제 자원 노드를 wildlife에 전달한다.
- 토끼·사슴은 같은 청크의 실제 PlantFood/Fiber를 2칸 이내에서만 소비한다. 토끼는 하루 1, 사슴은 하루 3단위가 충분한 섭식량이다. 부족한 양은 비례한 허기 감소만 준다.
- 사슴은 1년 미만의 재생 나무도 먹을 수 있다. 성목 목재는 먹이가 아니며, 어린 나무 소비는 기존 tree.remainingWood/node.quantity/재생 경로를 함께 갱신한다.
- 배고픈 초식동물은 실제 식물을 향해 시간당 한 칸씩 이동하며 청크·수면·주민 회피 제한을 지킨다. 포식자 회피가 우선한다. 이동만으로 먹지 않는다.
- 자원이 고갈되면 허기가 쌓이고 기존 번식 허기 제한·기아 사망이 작동한다. 기존 정적 carrying capacity는 안전 상한으로 유지하며 새 저장 필드를 만들지 않는다.
- 성인 노동 가능 주민은 배가 고프고 휴대 식량이 없으면, 16칸 내 실제 도달 가능한 토끼/사슴을 선택할 수 있다. 사슴은 내구도가 남은 절삭/벌목 도구를 요구한다. 가까운 늑대·호랑이가 있으면 사냥하지 않는다.
- 긴급 식량 선택은 저장 식량을 우선하고, 가까운 채집과 사냥의 거리를 비교한 후, 공급이 없으면 기존 탐색으로 이어진다. 새로운 Hunt는 기존 PlantFood **수요 태그**를 사용하지만 식물/고기 재고를 만들지 않는다.
- 사냥은 기존 ContextAction의 실제 이동·토큰·최소 20분 Core 경과시간을 지불한다. 도망간 같은 개체를 재추적하고 사라진 개체는 취소한다. 도달 시 실제 살아 있는 동물을 다시 확인한다.
- 잡기 성공은 seed/개체/주민/20분 시점의 결정론적 확률이다. 실패는 식량·허기·개체 수를 바꾸지 않는다. 사용한 도구는 실제 내구도를 소모한다.
- 성공하면 실제 한 개체를 제거하고 현장에서 먹어 허기를 줄인다. 중복 ACK/두 주민의 동일 개체 소비는 거부한다.
- Hunt/Hunted/HuntFailed는 enum 끝에 추가한다. 기존 ID·저장 레이아웃·재고 의미를 보존한다. 관측은 실패를 성공으로 표시하지 않으며 한국어 행동명을 제공한다.

## 검증

신규 `test_wildlife_subsistence`:
- 실제 식물 공유·고갈·원격 소비 거부·동일 일자 중복 소비 거부.
- 자원 없는 높은 forage 잠재력에서도 기아 사망.
- 성목 보호·어린 나무 소비/재생 수량 일치.
- 실제 이동 및 음수 좌표 청크 경계.
- 읽기 전용 계획, 어린이/휴대 식량/도구/포식자/거리 제한.
- 사냥 성공/실패의 개체·허기 보존과 중복 소비 거부.
- 실제 Simulation의 사냥 토큰, 조기/잘못된 ACK 거부와 binary 저장 후 같은 결과.

CMake/CTest/결정론·장기 안정성/WASM/Web 검증은 PR Actions에서 수행한다.
소스 작성이나 CI 시작만으로 PASS라고 표시하지 않는다.

## 남은 범위

고기 운반·보관·조리·상하는 고기·사체 청소는 이번 구현에 없다.
큰 동물의 남은 고기 회수도 없다. 현재는 한 번의 현장 식사로 소비한다.
물고기 먹이망, 실제 수목 잎/수관 biomass, 초식동물의 청크 간 이주,
장애물을 우회하는 동물 전용 pathfinder도 후속 작업이다.
야생동물 없는 저장에 동물을 새로 만들지 않는다.
기존 독립 prototype 테스트는 자원 포인터를 생략할 때 옛 잠재 먹이 모델로 유지된다.
Core 검증은 실제 Android 화면·성능·사냥 동작 애니메이션 검증을 대신하지 않는다.
