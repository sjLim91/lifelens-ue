## 2026-10-26 모델 정책 — Qwen 하나로 통합

사용자 승인: 현재보다 적합한 무료 모델을 선정하고 필요하면 교체한다. 기본 주민 언어 추론 모델은 **Qwen3-1.7B-q4f16_1-MLC** 하나로 정한다. 기존 Qwen2.5 0.5B는 기본 실행에서 교체하며, Ollama/LM Studio/llama.cpp의 첫 모델 자동 탐색·대체 전환과 별도 Shadow 모델 연결은 제품 경로에서 사용하지 않는다.

- 선정 이유: 현재 고정 WebLLM 0.2.86 지원 목록, Apache-2.0 모델 라이선스, 4비트 로컬 실행, 모바일을 포함한 실행 부담과 판단 능력의 균형. WebLLM의 해당 구성 VRAM 추정은 약 2,037 MB이며 **브라우저/3D 렌더러 메모리는 별도**다. 기기별 실행 보장은 아니다.
- 비교: 기존 0.5B는 실행 부담이 작지만 복합 판단 개선 여지가 있다. Qwen3.5 2B는 같은 목록에서 약 2,245 MB 및 low_resource_required=false, 4B는 더 큰 메모리를 요구한다. 최신/최대 모델을 무조건 기본값으로 채택하지 않는다.
- **이는 현재 제약에 따른 선정이며 실기기 A/B로 최적 성능을 입증한 결과는 아니다.** 실제 모델 품질·지연·메모리 검증은 추후 동일 Core 문맥/seed에서 측정한다. stub 회귀 통과를 실제 Qwen 추론 성공으로 보고하지 않는다.
- WebLLM의 non-thinking 옵션을 명시하여 짧은 결정 JSON을 요청한다. Core 허용 intent/actor/target schema로 생성 출력을 제한하고 수신 후에도 Core 계약 검증을 유지한다. 모델 자유 텍스트는 실행 권한이 아니다.
- 주민별 기억·성격·관계·계획은 독립이다. 하나의 모델 연산 자원을 공유하되 동시 추론은 1개이며 시효·취소·늦은 결과 차단을 유지한다.
- Qwen 미지원/다운로드 실패/메모리 부족이면 '추론 미연결'로 표시한다. 다른 모델이나 클라우드로 자동 대체하지 않는다. Core의 기존 생존·물리 실행은 유지하며 이를 Qwen의 실제 판단으로 표시하지 않는다.
- 이 정책은 모든 결정을 Qwen으로 이관하거나 Core Utility/물리 로직을 삭제했다는 뜻이 아니다. G1의 목표→행동→학습 연결은 별도 미완 작업이다.
- 기존 모델 캐시는 다른 앱·사용자 데이터와 구분 없이 삭제하지 않는다. 이전 가중치는 더 이상 로드하지 않으며 캐시 정리는 모델별 삭제 지원 검증 후 수행한다.
- 기존 M1-07의 다중 provider 방향 및 M11-05의 browser/PC 비교는 이 단일 모델 제품 정책에 맞춰 읽는다. no-LM 실행은 오류·생존 회귀 대조군이지 두 번째 사용자 AI 모드가 아니다.

검증: 로컬 cognition adapter 32개, Shadow 계약 16개, live controller 회귀 및 production Shadow 차단 통과. 전체 Web/WASM/CI와 배포 상태는 PR의 정확한 head 결과로 따로 확인한다. 실제 GPU 모델 로딩·추론 품질·Android 성능은 미측정이다.

- no-LM 기본 경로를 필수 검증한다. browser LM/PC loopback은 사용 가능한 환경에서 별도 비교하고 미지원은 미측정으로 남긴다. 모델 유무가 생존·Core 시간·정체성을 분리하지 않는다. LM 비교 미측정을 완전한 M11-05 완료로 처리하지 않는다.
- 같은 seed/ruleset/승인 입력 스트림의 replay를 비교한다. 모델의 새 응답을 재질의해 결정론을 주장하지 않는다. 장기 실행은 발전/생존을 강제로 보장하지 않고 사망·정체·실패 원인도 기록한다.
- 구현 중에는 해당 경로의 표적 회귀를 실행하고, 통합 때 변경 범위에 맞는 Core CTest/결정론/WASM/Web/Preflight 및 관련 장기 검증을 통과한다. 검증 축소나 임계치 완화로 완료 수를 올리지 않는다. 화면 캡처는 자동 병합 필수 게이트가 아니다.
- 보고는 매 납품 묶음마다 **새로 가능해진 행동 / 실제 실행 근거 / 남은 단절 / 다음 한 작업** 순서로 한다. 코드·CI·main 반영·배포 확인은 분리한다. 일정은 근거 없는 날짜 약속 대신 AL 순서와 차단 원인으로 관리한다.
- **G1이 우선 릴리스 목표**다. AL 통과만으로 M1~M3의 모든 확장 조건 또는 전체 86개 단위를 자동 완료하지 않는다. 기존 G2~G5와 장기 문명 목표는 보존한다.

## 0. 완성 범위와 절대 규칙
- **하나의 주민 = 하나의 지속적인 의사결정 주체**. 통합 resident agency를 거친다. 생존 반사·물리 실행·언어 추론은 같은 생명체를 구성하는 기능이지 서로 경쟁하는 NPC AI가 아니다. 한 로컬 언어모델의 연산 자원을 여러 주민이 공유해도 각 주민의 기억/믿음/계획/정체성은 독립이다.
- **세계의 유일한 권위는 Core**. AI는 목표·가설·계획을 제안; 실제 지형/도달/도구/자원/건강/교역/출산/사망 및 결과는 Core 검증·실행만이 변경한다.
- **발전을 스크립트로 강제하지 않는다**. 특정 날짜의 문명/시설/발명/결혼/출산/사육 해금 금지. 실패·멸종·이동·기술 소실 가능.
- **무료·오프라인/로컬 기본 경로 유지**. 유료 모델/API/클라우드 필수 의존성 금지. WebGPU/로컬 추론 미지원 기기에서도 동일 주민 agency와 Core 삶은 유지하되 거짓 GPT 수준 추론을 주장하지 않는다.
- **결정론**: 같은 시드·룰셋·승인된 인지 입력 스트림이면 같은 Core 결과. 외부 비결정론적 제안은 승인 저널에 기록하고 재생 시 재질의하지 않는다.
- **화면 캡처 테스트는 자동 병합 필수 게이트에서 제외**한다. 단, 수동 실제 기기 UX/리깅/성능 확인은 별도의 품질 작업으로 한다. 스크린샷을 작업 진행의 대체물로 삼지 않는다.
- **접속하지 않은 시간**은 두 방식으로 구분: (A) 재접속 후 놓친 시뮬레이션을 결정론적으로 따라잡는 방식, (B) 사용자 접속이 없어도 계속 계산하는 상주 로컬 실행기. 정적 GitHub Pages만으로 B는 성립하지 않는다. 백그라운드 실행을 무조건 보장한다고 주장하지 않는다.
- **완성 정의는 관측 가능한 능력**이다. 'GPT와 동급 범용 지능', '모든 문명 단계', '예측 불가한 결과의 보장' 등 평가 불가능한 주장 금지.

## 2. 시행 방식과 작업 카드
- **개발 묶음**(M0~M11)은 2~8개 개발단위로 구성하며, 그 안의 기능 단위는 관련 Core·WASM·Web·테스트를 **합쳐서 한 의미 있는 PR 또는 긴밀한 2~4개의 PR**로 낸다. 더 작은 임시 PR로 무의미하게 쪼개지 않는다.
- 우선순위는 상단 2026-10-26 개정의 P0-A/P0-B/P1/P2를 따른다. G1 인수 전 독립 side lane 신규 확장은 보류하며 실제 자율행동 루프를 직접 막는 의존성만 함께 해결한다.
- 상태 표현: \`[기반 있음]\` 기존 부분 코드 존재, \`[진행]\` 별도 PR, \`[미완]\` 기능 완료 증거 없음. 이 표는 개발 계획이므로 완료 확인 전 항목 체크 금지.
- 각 개발단위의 완료 조건은 **Core 수락/실행 결과, 실제 개인 기억/장기 상태 변화, 재현 가능한 회귀, 저장/복원**을 우선한다.

## 3. 기존 단계 의존성 — 범위 참조 / 실행순서는 2026-10-26 개정 우선

아래 도식과 A~H는 기존 범위 매핑이다. 현재 작업 착수 순서는 상단 AL-1→AL-2→AL-3→AL-4이며, M0/M1 전체 완료를 기다렸다가 M2/M3 실행 연결을 시작하지 않는다.

M0 실제 Main/PR 상태 감사, 측정 기준
 ├── P0 MAIN: M1 개인 AI·지각·기억
 │            ↓
 │          M2 자유 GoalSpec/가설/복합 Plan
 │            ↓
 │          M3 실제 Core 인과 실행·회고·재계획
 │            ↓
 │          M8 비스크립트 발명·창발 문명
 │
 ├── P1 SIDE: M4 생리·생활 + M5 사회·생애 ─┐
 ├── P1 SIDE: M6 야생·먹이사슬·사냥 ───────┤
 ├── P1 SIDE: M7 지역 지구/기후/다중 기원 ─┤

               └── M11 전체 장기검증/릴리스

**실제 개발 묶음 순서** (P0 중심; 독립 side lane은 충돌 없이 병렬):
1. 묶음 A: **M0-01~05 + M1-01~03**: 현재 의도/원인/출처/레거시 회귀 확정.
2. 묶음 B: **M1-04~07 + M2-01~03**: 한 주민의 기억과 동기에서 목표 후보 발행.

4. 묶음 D: **M3-01~06**: accepted thought→실제 행동→이벤트→회고 검증.
5. 묶음 E: **M4/M5의 생애·생존·공동 목표**, M6 실제 생태·사냥 및 M9 지속 실행을 병렬로 붙여 주민의 일상 다양화.
6. 묶음 F: **M7 현실 지구·두 원점 집단 + M10 관찰**을 붙여 서로 다른 환경에서 각자 살아가도록 구현.
7. 묶음 G: **M8 물질/능력 중심 창발적 발명·문명**, 쇠퇴와 재발견 실험.
8. 묶음 H: **M11 장기 인과·성능/Android 완성 QA** 및 문서/배포 릴리스.

## 4. 마일스톤별 제품 완료 게이트

**G1 개인 자율 생명**: 서로 다른 주민 두 명이 자신의 직접 지각으로 최소 두 개 경쟁 목표를 만들고, 다단계 계획을 실행하며, 같은 객관 물리 상태에서 실패 경험으로 다른 대안을 택한다. 단 하나의 agency 유지, 저장 재생 합치, 유료/네트워크 모델 부재 시 몸은 계속 산다.

**G2 사회·생태 연결**: 출생·돌봄·관계·교육·교역·사냥·포식·부상·회복/사망 중 다양한 실제 인과 사건이 누적된다. 실패/희생/인구 감소도 정상 가능. Core 사건 없이는 Web 성공 표시 없음.

**G3 지구와 시간의 연속성**: 동일 세계에 두 지역 집단 4+4명이 각각 독립적 환경에서 생존·탐색하며, 지구본 확대와 지역 전환은 Core 진실을 바꾸지 않는다. 재접속 catch-up은 필수, 사용자가 요구한 실제 비접속 상주 실행은 별도 무료 로컬 실행기가 가동 중일 때 충족됨을 명확히 표시한다.

**G4 창발 문명**: 1000일 이상 여러 시드에서 실제 재료·에너지·작업·발견·전파로 정착/도구/역할/교육/교역/문화 패턴이 형성되거나 실패하고, 세대 간 지속/쇠퇴/재발견이 가능하다. 특정 완성 시대를 사전 강제하지 않는다.

**G5 출하 품질**: Android 관찰 기기 검증, 사람/동물 동작 자연스러움, 한글 표시, 자원/저장/재생/장기 deterministic audit, 성능 병목 보고와 사용자에게 보이는 검증 가능한 진척률 모두 통과.

## 5. 운영 및 수치 보고 양식
각 큰 묶음마다 \`설계→구현→exact-head CI→Core 장기 인과 감사→main 병합→웹 배포→후속 갭\` 흐름으로 관리한다.

수치 보고는 다음을 분리한다.
- **구현률**: 계획된 개발단위 중 실제 main 병합 및 적합한 회귀 통과 수 / 확정 개발단위 수.
- **실행 성공률**: 승인 AI 의도 중 실제 Core 행동 토큰 및 실제 시도/완료/실패근거까지 연결된 비율.
- **자율성 증거**: 경험 주입/직접 학습 이전·이후의 후속 행동 A/B 차이와 리스크/비용/생존 영향.
- **창발성 증거**: 실지 자원·생산·사회·문화 상태가 여러 seed에서 비사전 지정 경로로 다르게 발전·붕괴.
- **제품 품질**: Core memory/snapshot 규모, long-run 실패 원인, LLM latency·local availability, Android FPS·메모리, 복원 일치.
- 아직 측정하지 않은 값은 \`미측정\`; PR 시작은 \`진행\`; CI 종료 전은 \`검증 중\`; main 미병합은 \`미반영\`으로 쓴다.
