## 0. 완성 범위와 절대 규칙
- **하나의 주민 = 하나의 지속적인 의사결정 주체**. 통합 resident agency를 거친다. 생존 반사·물리 실행·언어 추론은 같은 생명체를 구성하는 기능이지 서로 경쟁하는 NPC AI가 아니다. 한 로컬 언어모델의 연산 자원을 여러 주민이 공유해도 각 주민의 기억/믿음/계획/정체성은 독립이다.
- **세계의 유일한 권위는 Core**. AI는 목표·가설·계획을 제안; 실제 지형/도달/도구/자원/건강/교역/출산/사망 및 결과는 Core 검증·실행만이 변경한다.
- **발전을 스크립트로 강제하지 않는다**. 특정 날짜의 문명/시설/발명/결혼/출산/사육 해금 금지. 실패·멸종·이동·기술 소실 가능.
- **무료·오프라인/로컬 기본 경로 유지**. 유료 모델/API/클라우드 필수 의존성 금지. WebGPU/로컬 추론 미지원 기기에서도 동일 주민 agency와 Core 삶은 유지하되 거짓 GPT 수준 추론을 주장하지 않는다.
- **결정론**: 같은 시드·룰셋·승인된 인지 입력 스트림이면 같은 Core 결과. 외부 비결정론적 제안은 승인 저널에 기록하고 재생 시 재질의하지 않는다.
- **화면 캡처 테스트는 자동 병합 필수 게이트에서 제외**한다. 단, 수동 실제 기기 UX/리깅/성능 확인은 별도의 품질 작업으로 한다. 스크린샷을 작업 진행의 대체물로 삼지 않는다.
- **접속하지 않은 시간**은 두 방식으로 구분: (A) 재접속 후 놓친 시뮬레이션을 결정론적으로 따라잡는 방식, (B) 사용자 접속이 없어도 계속 계산하는 상주 로컬 실행기. 정적 GitHub Pages만으로 B는 성립하지 않는다. 백그라운드 실행을 무조건 보장한다고 주장하지 않는다.
- **완성 정의는 관측 가능한 능력**이다. 'GPT와 동급 범용 지능', '모든 문명 단계', '예측 불가한 결과의 보장' 등 평가 불가능한 주장 금지.

## 2. 시행 방식과 작업 카드
- **개발 묶음**(M0~M11)은 2~8개 개발단위로 구성하며, 그 안의 기능 단위는 관련 Core·WASM·Web·테스트를 **합쳐서 한 의미 있는 PR 또는 긴밀한 2~4개의 PR**로 낸다. 더 작은 임시 PR로 무의미하게 쪼개지 않는다.
- 우선순위: **P0** 통합 AI·진짜 개인 학습·세계의 안전성과 검증. **P1** 생명/사회/동물/지구/지속성. **P2** 개방형 발명·영상 품질·대규모 확장. 프로젝트 목적상 자율 AI P0를 먼저 완성하되 P1의 독립 Core 법칙/읽기 전용 관찰 레이어는 병렬 작업 가능.
- 상태 표현: \`[기반 있음]\` 기존 부분 코드 존재, \`[진행]\` 별도 PR, \`[미완]\` 기능 완료 증거 없음. 이 표는 개발 계획이므로 완료 확인 전 항목 체크 금지.
- 각 개발단위의 완료 조건은 **Core 수락/실행 결과, 실제 개인 기억/장기 상태 변화, 재현 가능한 회귀, 저장/복원**을 우선한다.

## 4. 마일스톤별 제품 완료 게이트

**G1 개인 자율 생명**: 서로 다른 주민 두 명이 자신의 직접 지각으로 최소 두 개 경쟁 목표를 만들고, 다단계 계획을 실행하며, 같은 객관 물리 상태에서 실패 경험으로 다른 대안을 택한다. 단 하나의 agency 유지, 저장 재생 합치, 유료/네트워크 모델 부재 시 몸은 계속 산다.

**G2 사회·생태 연결**: 출생·돌봄·관계·교육·교역·사냥·포식·부상·회복/사망 중 다양한 실제 인과 사건이 누적된다. 실패/희생/인구 감소도 정상 가능. Core 사건 없이는 Web 성공 표시 없음.

**G3 지구와 시간의 연속성**: 동일 세계에 두 지역 집단 4+4명이 각각 독립적 환경에서 생존·탐색하며, 지구본 확대와 지역 전환은 Core 진실을 바꾸지 않는다. 재접속 catch-up은 필수, 사용자가 요구한 실제 비접속 상주 실행은 별도 무료 로컬 실행기가 가동 중일 때 충족됨을 명확히 표시한다.

**G4 창발 문명**: 1000일 이상 여러 시드에서 실제 재료·에너지·작업·발견·전파로 정착/도구/역할/교육/교역/문화 패턴이 형성되거나 실패하고, 세대 간 지속/쇠퇴/재발견이 가능하다. 특정 완성 시대를 사전 강제하지 않는다.

**G5 출하 품질**: Android 관찰 기기 검증, 사람/동물 동작 자연스러움, 한글 표시, 자원/저장/재생/장기 deterministic audit, 성능 병목 보고와 사용자에게 보이는 검증 가능한 진척률 모두 통과.

## 5. 운영 및 수치 보고 양식
각 큰 묶음마다 \`설계→구현→exact-head CI→Core 장기 인과 감사→main 병합→웹 배포→후속 갭\` 흐름으로 관리한다.

수치 보고는 다음을 분리한다.
- **구현률**: 계획된 개발단위 중 실제 main 병합 및 적합한 회귀 통과 수 / 확정 개발단위 수.
- **실행 성공률**: 승인 AI 의도 중 실제 Core 행동 토큰 및 실제 시도/완료/실패근거까지 연결된 비율.
- **자율성 증거**: 경험 주입/직접 학습 이전·이후의 후속 행동 A/B 차이와 리스크/비용/생존 영향.
- **창발성 증거**: 실지 자원·생산·사회·문화 상태가 여러 seed에서 비사전 지정 경로로 다르게 발전·붕괴.
- **제품 품질**: Core memory/snapshot 규모, long-run 실패 원인, LLM latency·local availability, Android FPS·메모리, 복원 일치.
- 아직 측정하지 않은 값은 \`미측정\`; PR 시작은 \`진행\`; CI 종료 전은 \`검증 중\`; main 미병합은 \`미반영\`으로 쓴다.
