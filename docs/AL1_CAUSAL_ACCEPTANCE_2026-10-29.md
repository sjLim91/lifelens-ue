# AL-1 실제 목표·실행·개인 학습 인수 기록 — 2026-10-29~30

기준 main: `6d7fdbdac77663a1463305c888a44249d88be214` (#995). 기존 native Gather 학습 경로를 유지했다. **AL-1 전체 인수는 아직 완료로 표시하지 않는다.** 자연 발생 실패·회복 완료가 남은 인수 차단 조건이다. 최종 변경 커밋의 CI와 배포 검증은 PR/Actions 결과로 별도 확인한다. 전체 개발단위 완료 수는 **6/86 유지**이며 M0를 재개하지 않는다.

## 발견한 단절과 제품 수정

- `chooseResidentSensedResourceGoal()`의 선택된 typed 목표가 `beginPlan()`에서 버려졌다. 이제 개인 목표를 실제 pending Gather에 전달한다. native Gather도 후보를 점수화할 때 이미 계산하는 실제 개인 부족량(`target - storedCredit`)을 함께 보존한다. 긴급 식량/물 확보는 실제 필요와 소지량 0에서 발생한 최소 소비 전제 1개를 보존한다. 발행 이후 임의로 성공 목표를 붙이지 않는다.
- `ResidentGatherGoalLink`는 같은 주민의 목표 ID, 실행 토큰, 재료·목표 재고, 발행 당시 재고, 기한, 이전 실패 토큰·시도 수를 연결한다. 새로운 실행기나 별도 AI가 아니다. 기존 Core 경쟁·생존 우선·이동·채집·도구 배치 수량을 유지하고, 선택된 개인 목표 및 회복 단계는 남은 부족량으로 실행 수량을 제한한다.
- 실행 경계에서 실제 재고 및 원천 수량을 읽어 `achieved`, `progress-unmet`, `failed`, `already-satisfied`, `expired`, `interrupted-survival`을 구분한다. 부분 채집 성공은 목표 달성으로 올리지 않는다. 부분 진척은 같은 기존 필요/목표 경쟁에서 다시 평가하고, 실패는 안전한 대안을 찾거나 중단한다.
- 기존 즉시 회복은 이동 실패만 처리했다. 도착 후 실제 Core가 확인한 자원 소진/소실도 동일 주민의 직접 실패 기억을 통해 같은 재료의 현재 감지·경로 검증된 대안으로 이어진다. 목표 ID/조건을 보존하며 새 명령 토큰을 발행한다. 연결된 목표의 회복은 최대 3회·120분이며 더 긴급한 다른 생존 필요에 양보한다.
- 기존 엄격한 `action_experience`/`navigation_experience` 기억 형식과 출처 검증은 변경하지 않는다. 계획, 중단, 로그 문구만으로 성공 기억을 만들지 않는다. 저장은 검증·체크섬을 갖춘 선택적 v8 확장으로 연결하며 옛 저장의 진행 중 명령에 목표를 소급 생성하지 않는다.

## A/B: 무개입 새 게임의 동일 주민 인과 기록

`test_al1_natural_goal_causality`는 `setupNewGame()` 및 실제 `step()`만 실행한다. 목표/행동/자원/기억/위치/성격/필요를 주입하지 않는다. 발행 callback에서 실제 pending 상태를 읽으므로 같은 tick에 발행·완료되는 명령도 관측할 수 있다. 결과는 실행 이벤트뿐 아니라 주민 위치, 재고 증가, 원천 수량 감소, 정확한 개인 직접 기억과 교차 확인한다.

시간은 게임 내부 절대 분이다. 각 행의 첫 경험과 후속 행동은 같은 주민·동일 실제 기억을 연결한다.

발행 기록에는 개인 hunger/thirst/sleep/curiosity, 경쟁 신체 목표·효용, 선택 효용, 목표 재고를 포함한다. 목표 판정은 고정 성공 문구가 아니라 실제 `inventory_after >= target_quantity`로 검사한다. 이 증거가 모든 생애 목표나 M1~M3 전체 완료를 뜻하지 않는다.

## C: 특정 실제 기억 한 건만 제거한 대조

기존 검사는 최초 채집 기억 한 건을 고른 뒤 1일을 관측하여 두 시드 모두 명령 차이 0이었다. 강화된 검사는 자연 실행에서 실제 학습 발행이 발생한 바로 직전 분을 같은 새 게임에서 재현한다. World·RNG·runtime·다른 주민은 동일하고, 정확히 해당 주민/원천/시각의 실제 성공 기억 한 건만 제거한다. 그 한 건을 제자리에 재삽입한 전체 snapshot bytes가 원본과 같아야 한다.

| 시드 / 주민 | 기억 유지의 실제 발행 원천 | 한 건 제거의 실제 발행 원천 | 후속 실제 결과 |
|---|---|---|---|
| 874213954 / 2 | `8371056191655438253`, 토큰 70 | `4942088878575105140`, 토큰 70 | 양쪽 5개 채집. 유지 1636분, 제거 1638분 완료 |
| 4242001 / 3 | `8691838135534217779`, 토큰 205 | `6254270929236891479`, 토큰 205 | 양쪽 3개 채집, 5620분 완료 |

동일 토큰 번호는 독립 복제 상태의 같은 next-token에서 나왔기 때문이다. 서로 다른 실제 원천으로 이동·채집했다. 선호 점수만 비교한 결과가 아니다. 이 대조는 같은 객관 상태에서 개인 경험 차이가 실제 행동 차이를 만든다는 근거다.

## E/F: 회귀 및 인수 경계
