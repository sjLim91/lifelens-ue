## 1. North Star

LifeLens의 장기 목표는 다음과 같다.

> **초기 인간 4명으로 시작하여, 외부 스크립트가 시대를 강제하지 않고 생존·지식·발견·사회 변화의 결과로 원시사회부터 현재 인류 수준을 지나 아직 현실세계가 마주하지 않은 미지의 미래문명까지 자율적으로 발전할 수 있는 관찰형 시뮬레이션.**

LifeLens는 특정 시대를 순서대로 해금하는 기술트리 게임이 아니다.
각 주민과 집단이 실제 생활에서 겪는 문제, 자원, 지식, 관계, 환경, 제도와 선택이 다음 발전 가능성을 만든다.

같은 시간만 흘렀다고 같은 시대에 도달해서는 안 된다.
어떤 세계는 오랫동안 정체할 수 있고, 어떤 세계는 지식을 잃거나 붕괴할 수 있으며, 어떤 세계는 빠르게 과학·산업·AI·우주 문명으로 발전할 수 있다.

## 2. 절대 원칙

### 2.1 Core / World가 유일한 진실이다

- 자원, 인구, 지식, 기술, 시설, 에너지, 생산, 사회 상태와 결과는 Core / World가 결정한다.
- UI / Character / WorldPresentation은 권위 있는 read/action contract를 소비한다.
- 화면에 보인다는 이유로 기술, 시설, 자원, 사회 변화가 생성되어서는 안 된다.

### 2.2 시간 경과만으로 시대를 해금하지 않는다

금지 예:
- 100년 경과 → 청동기 자동 진입
- 500년 경과 → 산업혁명 자동 발생
- 2100년 → 핵융합 자동 해금

대신 실제 선행 조건이 필요하다.

예:
- 구리 + 주석 + 적절한 제련/주조 능력 → 청동 기술 후보
- 고온 열원 + 정밀 가공 + 재료 지식 + 회전/압력 제어 → 고급 기계 기술 후보
- 전력 생산 + 도체/절연체 + 논리/계산 지식 → 전자/컴퓨팅 기술 후보
- 고성능 계산 + 센서 + 제어 + 자동기계 → 자율로봇/AI 생산 체계 후보

### 2.3 무료 인프라를 지급하지 않는다

New Game에는 자연환경과 창립자만 존재한다.
집, 농장, 도로, 저장고, 화장실, 작업장, 발전소, 연구소, 컴퓨터, 우주선이 시대 라벨 때문에 생성되어서는 안 된다.

모든 인프라는 실제 자원, 노동, 지식, 위치와 운영 조건을 필요로 한다.

### 2.4 발전은 되돌릴 수 있어야 한다

문명은 항상 전진하지 않는다.

- 숙련자가 사망하고 지식 전승에 실패할 수 있다.
- 시설이 파괴되거나 유지보수 부족으로 기능을 잃을 수 있다.
- 핵심 자원이 고갈될 수 있다.
- 질병·환경 변화·분쟁·이주로 생산망이 붕괴할 수 있다.
- 기술은 기록만 남고 실제 재현 능력을 잃을 수 있다.
- 잃어버린 지식을 후대가 다시 발견할 수 있다.

### 2.5 결정론과 Save/Load 계약을 유지한다

같은 WorldSeed / PopulationSeed / ruleset / 입력 / snapshot에서 같은 결과를 재현할 수 있어야 한다.

미래 기술 생성도 무제한 난수 문장 생성이 아니라 안정적인 ID와 규칙을 가진 결정론적 시스템이어야 한다.

## 3. 왜 고정 시대 트리만으로는 부족한가

`StoneAge -> BronzeAge -> IronAge -> Modern -> Future` 같은 단일 enum은 초기 개발에는 편하지만 장기적으로 세 가지 문제가 있다.

1. 개발자가 마지막으로 작성한 시대가 시뮬레이션의 영구 상한이 된다.
2. 서로 다른 문명이 결국 같은 기술 순서를 밟게 된다.
3. 현실에 아직 없는 미래를 표현하려면 개발자가 미리 정답을 알아야 한다.

따라서 시대는 **원인**이 아니라 **관찰용 요약 결과**여야 한다.

LifeLens 내부 발전의 실체는 아래 네 층으로 분리한다.

---

## 4. 문명 발전의 4계층 모델

### 4.1 Knowledge — 개인/집단이 알고 있는 것

예:
- 날카로운 돌을 만드는 방법
- 불을 유지하는 방법
- 특정 식물이 잘 자라는 조건
- 구리 광석을 가열하면 금속을 얻을 수 있다는 사실
- 전하/전류에 대한 이론
- 유전 정보에 대한 이해

지식은 개인이 소유할 수 있고, 관찰·교육·실험·기록을 통해 전파된다.

### 4.2 Capability — 실제로 할 수 있는 능력

Capability는 문명의 장기 확장 핵심이다.

예:
- `Cut`
- `Dig`
- `Smelt`
- `CastMetal`
- `GenerateMechanicalPower`
- `GenerateElectricity`
- `StoreElectricity`
- `PrecisionMachine`
- `Compute`
- `NetworkInformation`
- `AutomateProduction`
- `EditGenome`
- `LaunchToOrbit`
- `ClosedLoopLifeSupport`

Capability는 단순 지식 보유만으로 성립하지 않는다.
필요한 도구, 시설, 에너지, 재료, 숙련, 운용 경험이 실제로 존재해야 한다.

### 4.3 Technology — 구체적인 발명/공정/시스템

Technology는 여러 Knowledge / Capability / 자원 조건을 실제 형태로 묶은 것이다.

예:
- CopperSmelting
- BronzeCasting
- Irrigation
- PrintingPress
- SteamEngine
- ElectricMotor
- SemiconductorComputer
- IndustrialRobot
- FusionReactor
- GeneEditingPlatform
- OrbitalHabitat

현재 존재하는 `Technique` 기반 원시 기술은 폐기하지 않는다.
장기적으로 stable Capability/Technology ID 체계로 매핑하면서 호환한다.

### 4.4 Civilization Transformation — 기술이 사회를 바꾸는 결과

LifeLens는 기술 목록만 늘어나는 게임이 아니다.
기술이 생활과 사회구조를 실제로 변화시켜야 한다.

예:
- 농업 → 정착 증가 → 인구 밀도 증가 → 저장/분배 필요 → 전문직 등장
- 인쇄 → 지식 복제 비용 감소 → 교육 확산 → 연구 인구 증가
- 산업 자동화 → 생산성 증가 → 직업 구조 변화 → 소득/분배 갈등
- 수명 연장 → 세대교체 지연 → 가족/상속/제도 변화
- 고도 AI → 연구/생산 자동화 → 기술 발전 가속 또는 규제/거부

---

## 5. 표준 혁신 루프

문명의 새로운 발전은 기본적으로 다음 순환을 따른다.

`문제/욕구/기회`
→ `관찰`
→ `가설/실험`
→ `실패 또는 발견`
→ `재현`
→ `교육/지식 확산`
→ `도구/시설 건설`
→ `실제 운영`
→ `생산성/생활/사회 변화`
→ `새로운 문제/기회`

예를 들어 식량 불안이 반복되면 주민은 채집만 계속하는 것이 아니라 재배 가능성을 탐색할 수 있다.
재배가 성공하면 저장·토지·노동 분배 문제가 생기고, 그것이 다시 새로운 기술과 제도의 동기가 된다.

이 루프는 미래 기술에도 동일하게 적용한다.

---

## 6. 연구와 발명의 동기

기술 후보는 무작위 시대 보상으로 생성하지 않는다.
다음과 같은 실제 압력이 연구/실험 utility를 만든다.

- 생존 문제: 식량, 물, 주거, 질병, 온도
- 생산 병목: 노동 부족, 운반거리, 낮은 생산성
- 자원 문제: 고갈, 희소성, 대체재 필요
- 에너지 문제: 열/동력/전력 부족
- 정보 문제: 기억 손실, 교육 비용, 통신 지연
- 사회 문제: 분배, 치안, 조정, 갈등
- 탐험 동기: 새로운 자원/거주지
- 호기심/창의성/개인 성향
- 경쟁/협력 관계
- 이전 기술이 만들어낸 새로운 가능성

모든 주민이 동일한 연구자가 될 필요는 없다.
성격, 선호, 교육, 전문화, 사회적 지위와 경험이 연구 행동에 영향을 줄 수 있다.

---

## 7. 기술 후보의 유효성 계약

미래 기술을 개방적으로 만들더라도 마법처럼 보이면 안 된다.
기술 후보는 최소한 다음 계약을 충족해야 한다.

### 7.1 선행 지식
관련 원리나 경험이 존재해야 한다.

### 7.2 Capability 조합
해당 기술을 실현할 수 있는 실제 능력 집합이 필요하다.

### 7.3 재료/자원
필요한 물질이나 대체 가능한 재료가 실제 세계에 존재해야 한다.

### 7.4 에너지
기술이 요구하는 에너지 형태와 규모를 공급할 수 있어야 한다.

### 7.5 제조/정밀도
필요한 제작 정밀도, 내구도, 공정이 가능해야 한다.

### 7.6 인력/조직
개인이 만들 수 없는 규모라면 교육된 인력, 협업, 조직과 공급망이 필요하다.

### 7.7 운영/유지보수
한 번 만들었다고 영구적으로 유지되지 않는다.
연료, 부품, 숙련, 유지보수 체계가 필요하다.

---

## 8. 사회적 수용과 기술 확산

발견과 보급은 다른 사건이다.

새 기술이 발견되어도 다음 이유로 널리 쓰이지 않을 수 있다.

- 너무 비싸다.
- 필요한 자원이 부족하다.
- 기존 방식보다 이득이 작다.
- 위험성이 높다.
- 교육받은 운용자가 부족하다.
- 사회적/제도적 거부가 있다.
- 특정 집단이 독점한다.

따라서 Technology에는 최소한 다음 상태가 구분될 수 있어야 한다.

`Observed / Experimental / Reproducible / Operational / Diffusing / Common / Declining / Lost`

정확한 enum/데이터 구조는 구현 단계에서 결정하되, 개념적으로 **발견 = 즉시 문명 전체 보급**이 되어서는 안 된다.

---

## 9. 교육·기록·전문화

현재의 물리적 KnowledgeTeaching은 장기 문명의 중요한 씨앗이다.
향후 발전하면서 지식 전달 수단이 바뀐다.

- 대면 관찰/교육
- 가족/도제 전승
- 기호/문자 기록
- 학교/도서관
- 인쇄/대량복제
- 전자통신
- 디지털 네트워크
- AI 보조 학습

지식 전달 비용과 정확도가 변화하면 문명의 연구 속도와 회복력이 크게 달라진다.

전문화 역시 필요하다.

- 농업
- 건설
- 금속
- 의료
- 교육
- 연구
- 행정
- 운송
- 제조
- 정보/계산

전문화는 생산성을 높이는 대신 상호의존성과 공급망 위험을 만든다.

---

## 10. 경제·제도·사회 변화

현재 장기 로드맵에서 `경제/사회`를 너무 뒤에 둘 수 없다.
산업·정보·AI 문명은 자원 배분과 조직 없이 자연스럽게 발생하기 어렵다.

필요한 기반:
- 소유/공유/분배 규칙
- 노동 및 역할
- 교환/거래
- 저장/재고/수요
- 전문화
- 집단 의사결정
- 규칙/제도
- 갈등 조정
- 교육/연구 조직

정치/거버넌스는 특정 현실 정치체제를 정답으로 강제하지 않는다.
집단 크기, 자원 압력, 신뢰, 갈등, 기술과 역사에 따라 다양한 조직 형태가 나타날 수 있는 일반 메커니즘을 목표로 한다.

---

## 11. 쇠퇴·붕괴·지식 소실·재발견

LifeLens의 문명사는 항상 우상향하지 않는다.

가능한 흐름:

`고도 전문화`
→ `공급망 의존 증가`
→ `핵심 자원/인구 충격`
→ `시설 운영 중단`
→ `Capability 상실`
→ `기술은 기록에만 존재`
→ `후대의 재발견`

이 구조는 장기 관찰에서 매우 중요하다.
같은 세계 안에서도 여러 번의 발전과 쇠퇴가 발생할 수 있다.

---

## 12. 역사적 발전 구간은 관찰용 라벨이다

다음 구간은 개발 콘텐츠와 Observer 요약을 위한 편의적 분류다.
**Core의 강제 시대 게이트가 아니다.**

1. 자연 생존 / 채집
2. 정착 / 농경 / 초기 주거
3. 구리 / 청동 / 철 / 도시화
4. 문자 / 제도 / 장거리 교역 / 과학적 축적
5. 기계화 / 증기 / 산업화
6. 전기 / 화학 / 대량생산 / 현대 인프라
7. 전자 / 컴퓨터 / 네트워크 / 정보사회
8. AI / 로봇 / 고도 자동화
9. 고밀도 에너지 / 첨단 재료 / 생명공학
10. 행성 규모 관리 / 우주 거주 / 행성간 활동
11. 미지의 미래 문명

한 문명이 7번에서 8번으로 '레벨업'하는 것이 아니다.
실제 보유 Capability와 사회 상태를 Observer가 사람이 읽기 쉬운 이름으로 요약할 뿐이다.

---

## 13. 미지의 미래를 만드는 방법

현실에 아직 없는 미래 기술은 개발자가 개별 이름을 무한히 하드코딩하는 방식으로는 끝이 없다.

따라서 장기적으로 기술 후보를 **기존 Capability의 조합 + 세계 문제 + 재료/에너지 제약 + 연구 능력**에서 생성할 수 있는 구조로 확장한다.

예시:

### 에너지 경로
`고급 재료 + 초전도 지식 + 플라즈마 제어 + 고성능 계산`
→ 새로운 고밀도 에너지 기술 후보

### 생명/의료 경로
`유전학 + 인공장기 + 신경과학 + 자동의료`
→ 수명/회복/신체 보조 기술 후보

### 우주 경로
`고밀도 에너지 + 자율로봇 + 폐쇄생태계 + 궤도제조`
→ 장기 우주 거주/행성간 산업 후보

### 정보/지능 경로
`분산 컴퓨팅 + 자율 AI + 로봇 생산 + 네트워크`
→ 인간 중심 노동구조를 넘어선 새로운 생산/의사결정 형태 후보

중요한 점은 '그럴듯한 이름 생성'이 아니라 **실제 시뮬레이션 효과가 정의되는 것**이다.
새 기술은 에너지, 생산, 계산, 운송, 정보, 건강, 자동화, 재료, 환경 등의 측정 가능한 capability를 변화시켜야 한다.

---

## 14. 기술적 가속 / 특이점 유사 현상

LifeLens는 '특이점 이벤트'를 날짜에 맞춰 발생시키지 않는다.

하지만 다음과 같은 피드백이 실제로 성립하면 발전 속도가 비선형적으로 빨라질 수 있다.

`계산 능력 증가`
→ `연구 효율 증가`
→ `자동화 증가`
→ `생산 여유 증가`
→ `교육/연구 인구 증가`
→ `더 높은 계산/연구 능력`

반대로 사회적 거부, 에너지 부족, 분쟁, 환경 피해, 공급망 붕괴로 이 가속이 멈출 수도 있다.

---

## 15. 현재 구현에서 Open-Ended 구조로의 마이그레이션

현재 primitive civilization 구현은 버리지 않는다.
이미 존재하는 `Technique`, facility, item, material, knowledge transmission, physical ContextAction은 미래 시스템의 첫 실증 데이터다.

### 단계적 전환

1. 기존 primitive `Technique` / Item / Facility enum과 save ordinal은 안정적으로 유지한다.
2. 별도 stable `CapabilityId` / `TechnologyId` 개념을 추가한다.
3. 기존 기술을 Capability graph의 초기 노드에 매핑한다.
4. 신규 중·후기 문명 콘텐츠는 가능하면 registry/data-driven definition으로 추가한다.
5. snapshot에는 이름 문자열이 아니라 stable ID + definition/schema version을 저장한다.
6. UI는 내부 구조를 재판단하지 않고 Core가 제공하는 civilization read model을 표시한다.

이 방식으로 초기 문명 코드를 대규모 재작성하지 않고 점진적으로 확장한다.

---

## 16. 장기 시뮬레이션을 먼저 견뎌야 한다

미래 문명 목표는 수백~수천 년 진행을 전제로 한다.
따라서 기능을 계속 추가하기 전에 다음 기반을 갖춘다.

- per-frame catch-up simulation budget
- 인구 증가 시 CPU / memory 안정성
- residue / WorldPresentation refresh 비용 관리
- inactive/distant entity LOD 또는 coarse simulation 전략
- snapshot 크기/복원 비용 관리
- multi-century deterministic headless regression

'미래 기술 100개'보다 먼저 '시간을 오래 돌려도 죽지 않는 시뮬레이션'이 필요하다.

## 17. Observer 경험

주 화면은 관찰을 방해하지 않도록 단순하게 유지한다.

기본 화면:
- 현재 행동
- 감정/상태의 핵심 요약
- 시설/문명 변화의 중요한 사건

상세 화면:
- 개인이 알고 있는 지식
- 기술을 누구에게서 배웠는지/어디서 발견했는지
- 현재 Capability
- 실험/실패/발견 이력
- 직업/전문화
- 가족/관계
- 문명 변화의 원인과 영향

문명 전체 Observer:
- 현재 실제 운용 가능한 Capability
- 실험 중인 Technology
- 보급/쇠퇴 중인 기술
- 자원/에너지/생산 병목
- 주요 사회 변화
- 장기 역사 타임라인

## 19. Acceptance Principles for every future civilization slice

새 문명 기능은 최소한 다음을 만족해야 한다.

- 필요한 선행지식 없이 공짜로 해금되지 않는다.
- 필요한 자원/에너지/시설 없이 결과를 생성하지 않는다.
- 행동은 가능한 한 실제 이동/상호작용/ACK를 거친다.
- 지식 전파는 권위 있는 전달 경로를 사용한다.
- Save/Load 후 중복 결과를 만들지 않는다.
- 동일 seed/ruleset에서 결정론을 보존한다.
- Presentation은 결과를 만들어내지 않는다.
- 기존 생존 Needs를 새로운 기술 utility가 무한정 압도하지 않는다.
- 실패/쇠퇴/지식 소실이 가능한 구조를 막지 않는다.
- 기술은 Observer용 이름뿐 아니라 실제 시뮬레이션 효과를 가진다.

## 20. 최종 제품 정체성

LifeLens에서 관찰자는 문명을 직접 조종해 정답 루트를 밟게 만드는 플레이어가 아니다.

관찰자가 보고 싶은 것은 다음이다.

> **“처음에는 네 명뿐이었는데, 이 세계의 사람들이 스스로 살아남고, 사랑하고, 아이를 낳고, 배우고, 실패하고, 발견하고, 사회를 만들더니 어느 순간 우리가 알지 못하는 미래까지 갔다.”**

이 결과가 스크립트가 아니라 시뮬레이션의 연쇄적 결과로 나타나는 것이 LifeLens의 최종 방향이다.
