## Overall verdict

The current Core/persistence/compile baseline is healthy: tests, deterministic continuation, structural checks and UE 5.6 compilation all pass.

However, static integration review found runtime synchronization gaps that automated compile/test gates do not detect. These should be fixed before deeper environment-health-memory feedback or large civilization physical-expression work.

## P0 — Core ↔ World physical execution synchronization

Current Core physical action completion and Unreal movement/arrival are not one transaction.

Example: Emergency toilet uses 2 Core simulation ticks. With the current default 0.6 real seconds per simulation minute, Core can complete the toilet action and create residue in roughly 1.2 real seconds. Unreal may be moving the actor about 650 uu at a default 180 uu/s and has not yet reached the use point.

Consequences:
- Core can apply need effects/consequences before the visible actor arrives.
- the Core directive may return to Idle and Unreal can clear movement before reaching the intended point.
- Core may classify an action as Emergency while Unreal independently finds a Preferred/Primitive/Natural anchor.

Required direction:
`Core intent/request → World resolves actual affordance → movement → arrival → use confirmation → Core completion/consequence → release`

Add a stable action token/phase and completion/failure acknowledgement. Core remains the simulation authority, while the physical World reports execution facts instead of independently completing a second action interpretation.

## P0 — One canonical affordance and position mapping

Core outdoor sanitation coordinates and Unreal emergency fallback locations are currently generated by different algorithms.

Core:
- WorldSeed + CharacterId
- 8 grid directions
- 5–7 Core tiles from Core origin

Unreal:
- stable Resident FGuid + intent
- arbitrary 0–359 degree direction
- 650 uu from `ALLWorldDirector`

The authoritative residue can therefore be stored somewhere different from where the visible character acted.

Required direction:
- one canonical Grid ↔ Unreal World transform contract.
- the resolved physical action location must be included in execution result/ack.
- residue/environment consequence must use that same authoritative physical location.

## P0 — Dynamic resident actor reconciliation

`ALLWorldDirector::SpawnResidents()` currently runs only during BeginPlay.

Core can create residents later through birth, but WorldDirector does not reconcile newly created/deceased residents into the actor set.

Current spawn placement also has only four offsets and uses modulo indexing, so a loaded population above four can overlap existing spawn positions.

Required direction:
- reconcile resident actors from stable ResidentId whenever authoritative population changes.
- spawn new births, retire/despawn deceased presentation when appropriate, preserve existing actors.
- use scalable deterministic/non-overlapping placement rather than a four-slot modulo table.
- never hard-code runtime population to the initial four founders.

## P0 — Dynamic affordance registration

`CollectActivityAnchors()` currently runs only at BeginPlay.

If civilization later creates a latrine, bed, storage/crafting station or another usable affordance at runtime, WorldDirector will not automatically know about the newly created anchor.

Required direction:
- dynamic register/unregister lifecycle for activity anchors, or safe periodic/event-driven reconciliation.
- civilization physical expression must be immediately usable after creation.

## P0 — Actual-world facility state is not reconciled with Core availability

Production Core New Game correctly starts with zero fabricated modern SmartObjects after PR #68. Unreal can nevertheless contain real `ALLActivityAnchor` facilities.

Those Unreal anchors are not currently registered as authoritative Core physical opportunities. This can make Core think only Emergency is available while Unreal visually uses a Preferred anchor. Eat/Drink can be even stricter: Core may refuse the goal without inventory/resources even though Unreal has a visible facility.

Required direction:
- do not reintroduce fabricated bootstrap SmartObjects.
- add an authoritative affordance-resolution/execution contract so Core intent/need logic and World physical availability share one resolved outcome.
- facility quality/tier and resource consumption must be reported once, not simulated independently by Core and Unreal.

## P1 — Physical position persistence / reload continuity

Core snapshot persists runtime grid positions, but current resident read/action DTOs do not expose authoritative position and WorldDirector respawns actors at fixed initial offsets after load.

Required direction:
- expose/restore a canonical physical position or World-owned persisted transform mapped to Core identity.
- Save/Load must not reset visible residents to founder spawn positions while Core believes they are elsewhere.

## P1 — Dormant competing Unreal decision component

Every `ALLResidentCharacter` owns `ULLDecisionComponent`, which exposes a `ChooseAction()` utility based on legacy projected Needs. It is currently not ticked and WorldDirector does not call it, so it is not active authority today.

It remains a latent competing action chooser that could be called from Blueprint later.

Required direction:
- remove/deprecate it from production resident authority, or clearly restrict it to test/debug compatibility with no gameplay call path.

## P1 — Unreal compile workflow path coverage

`unreal-linux-compile.yml` currently triggers on Simulation/World/build/target/project paths but not all Unreal C++ source areas such as Characters, AI, UI, Save and Core.

This means a Character-only C++ PR can miss the Linux UHT/UBT gate unless another triggering path changes.

Required direction:
- preferably trigger on `Source/LifeLens/**` for C++ module changes while leaving pure Content/docs changes out of the expensive compile.

## P1 — Legacy snapshot migration fixture coverage

The binary codec declares current format v4 with supported legacy versions v1–v3 and contains migration logic. Current tests strongly cover v4 roundtrip, corruption handling, Save/Load and deterministic continuation.

A dedicated fixture test that actually decodes representative v1/v2/v3 bytes was not found during this verification.

Required direction:
- add stable migration fixtures or deterministic old-format builders and assert v1/v2/v3 → current state migration behavior.
